- 2026-10-12 — Demo rig: this laptop (Ryzen 7 7730U, 13.9 GB) as server via Windows Mobile Hotspot, 3 Android phones; fallback is Ubuntu with a NetworkManager hotspot + dnsmasq. No new libraries for QR/page images (page PNGs written with stdlib).
- 2026-10-12 — Refusal is two layers, not one score. (1) Before the model: refuse when no retrieved chunk has a keyword (FTS) hit AND the best cosine similarity is below `REFUSAL_THRESHOLD` (placeholder 0.5, calibrate on the dev split). (2) After the model: the prompt makes it reply exactly `NOT_IN_TEXTBOOK` when the sources don't answer, and an answer with no valid `[Sn]` marker is also refused. Reason: measured on 12 Oct, cosine similarity alone could not separate "What is photosynthesis?" (0.44) from "Why is Bhimbetka important?" (0.44), and an RRF-score threshold refuses every cross-lingual question. Gate inputs and retrieved pages are sent in each `done`/`refused` event for calibration and recall@k.
- 2026-10-12 — Malayalam text is normalised the same way at ingest and query time (old-style chillu "consonant + virama + ZWJ" → atomic chillu, ZWNJ dropped), and question words are stripped of common case endings before the keyword search. Reason: Tesseract emits the old encoding while phone keyboards type the atomic one, so identical-looking words never matched.
- 2026-10-12 — Chat model runs on the Radeon iGPU via the Vulkan build of the same llama.cpp release (b11556), with `-ngl 99`, flash attention off and an f16 KV cache. Reason: llama-bench on this laptop measured Gemma 4 E2B prefill at 53 tok/s on CPU vs 146 tok/s on Vulkan (pp512); with flash attention on, Vulkan prefill fell to 35–46 tok/s (pp1024), and a q8 V cache requires flash attention. The embedder stays on the CPU build. Settings live in `.env` (`LLM_GPU_LAYERS`, `LLM_KV_TYPE`, `LLM_FLASH_ATTN`).
- 2026-10-12 — Answer target: first word in 10–15 s (team decision). Retrieved-context budget set to 600 bge-m3 tokens: measured first-word time 4.7–10.7 s (EN and ML) vs 14–23 s at 900, single runs under memory pressure; to be re-measured by `eval/bench.py`. No model "thinking" text is shown to students (ANSWER_POLICY §8); the phone shows progress steps instead.

- 2026-10-13 — Admin is not like other logins: created on the server with `python -m ruralminds.admin init` (printed one-time recovery code), and the app only accepts admin sign-in and admin requests from the server machine itself (127.0.0.1). Passwords are scrypt-hashed (stdlib); sessions are random tokens stored hashed, in an HttpOnly SameSite=Strict cookie; students are signed out after 30 min idle (shared phones). Plain HTTP means passwords cross the hotspot's WPA2 Wi-Fi unencrypted at the HTTP level; the HTTPS option stays Phase 2.
- 2026-10-13 — Teacher upload in the browser moves into Phase 0. The file streams to a `.part` file under a byte cap (default 60 MB, 400 pages) while hashing, must open in pdfium, is fsynced and atomically renamed; duplicates by sha256 are refused. Ingestion runs one job at a time in a separate lower-priority process; OCR is cached per page, so after a power cut the job resumes where it stopped (verified 13 Oct: 98 → 51 → 35 pages left across two kills). A janitor removes unreferenced `.part` files, PDFs and OCR caches. PDFs are not recompressed (no allowed library); the database holds only text and vectors.
