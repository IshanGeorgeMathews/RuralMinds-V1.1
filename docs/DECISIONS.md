- 2026-10-19 — **W5 part 1, load control** (no per-student data; all in memory):
  - **Queue:** a FIFO answer queue with direct hand-off. `leave()` is the single exit for answered, refused and disconnected requests. The response closes the answer stream via `aclosing`, so a phone that leaves gives back its place or slot at once. A slot is taken just before the first model call: before the search rewrite for other-language questions (the rewrite used to bypass the queue), otherwise after the gate (refusals stay instant).
  - **Waiting phones:** a live place in line every 3 s (also an SSE keep-alive), with a wait estimate from the measured gap between finished answers (2 slots share one GPU, so slots × answer time would overstate capacity), shown rounded.
  - **Shedding:** turn away when the predicted wait exceeds `max_wait_s` = 180 s, or 30 are waiting.
  - **One question per phone:** one in flight per signed-in phone (session-token hash, 5-min TTL backstop; fixes D5).
  - **Notes:** the notes process waits until all llama-server slots are idle before each call. Known gap: the API cannot see a notes call in progress, so llama-server briefly queues a student request behind it.
  - **Bench:** reports shed requests and goodput over admitted requests separately.
  - **Measurement:** no capacity change is expected from part 1, so the after-bench runs after the exam chips (part 2), on battery like the 22:50 baseline.
